## Описание модулей и функций
### Модуль masks
1. Функция **get_mask_card_number** для маскировки номера банковской карты.\
Принимает на вход номер карты и возвращает ее маску в формате:\
XXXX XX** **** XXXX,
где X — это цифра номера.\
Остаются видимыми только первые 6 цифр и последние 4 цифры, номер разбит по блокам по 4 цифры.\
Пример работы функции:
Входной аргумент: 7000792289606361\
Выход: 7000 79** **** 6361\
  
2. Функция **get_mask_account** для маскировки номера банковского счета.\
Функция принимает на вход номер счета и возвращает его маску в формате:\
**XXXX, где X — это цифра номера.\
Остаются видимыми только последние 4 цифры номера.\
Пример работы функции:\
Входной аргумент: 73654108430135874305\
Выход: **4305


### Модуль widget
1. Функция **mask_account_card** для обработки информацию как о картах, так и о счетах.\
Принимает один аргумент — строку с типом и номером карты или счета и возвращает строку с замаскированным номером.\
**Примеры работы функции:**\
**Для карты**\
Входной аргумент: Visa Platinum 7000792289606361\
Выход: Visa Platinum 7000 79** **** 6361\
**Для счета**\
Входной аргумент: Счет 73654108430135874305\
Выход: Счет **4305


2.  Функция **get_date**\
Принимает на вход строку с датой в формате **"2024-03-11T02:26:18.671407"**\
и возвращает строку с датой в формате **"ДД.ММ.ГГГГ"**\
Пример: ("11.03.2024")

### Модуль processing
1. Функция **filter_by_state**\
Принимает список словарей и опционально значение для ключа state (по умолчанию 'EXECUTED').\
Возвращает список словарей, содержащий только те словари, у которых ключ "state" соответствует указанному значению.\

**Пример:** выход функции со статусом по умолчанию 'EXECUTED':\
```
[{'id': 41428829, 'state': 'EXECUTED', 'date': '2019-07-03T18:35:29.512364'},
 {'id': 939719570, 'state': 'EXECUTED', 'date': '2018-06-30T02:08:58.425572'}]
```
2. Функция **sort_by_date**\
Принимает список словарей и необязательный параметр - порядок сортировки (по умолчанию — убывание).\
Возвращает новый список, отсортированный по дате (значениям ключа "date").\
Для корректной работы функции в словаре должен быть ключ "date", значение которого должно быть строго задано в формате:\
**"ГГГГ-ММ-ДДТЧЧ:Мн:Ск.миксек"**,\
где "T" - англ. Т, отделяющая дату от времени, Мн- минуты, Ск - секунды, миксек - микросекунды.\
Длина строки должна быть 26 символов.


3.  Функция **process_bank_search**
Принимает на вход список словарей с данными о банковских операциях и строку поиска.\
Возвращает список словарей, у которых в описании (поле "description") есть данная строка.\
Если операции с искомым описанием не найдены, возвращает пустой список.


4.  Функция **process_bank_operations**
Принимает список словарей с данными о банковских операциях и список категорий операций.\
Возвращает словарь, в котором ключи — это названия категорий,\
а значения — это количество операций в каждой категории.\
Если категории не заданы, возвращает пустой словарь.


### Модуль generators
Содержит функции, реализующие генераторы для обработки данных\
1. Функция **filter_by_currency**\
Принимает на вход список словарей, представляющих транзакции.\
Функция возвращает итератор, поочередно выдающий транзакции, в котороых валюта операции\
соответствует заданной (например, "RUB", "USD", "EUR").


2. Функция **transaction_descriptions**
Принимает список словарей с транзакциями и возвращает описание каждой операции по очереди.\ 


3. Функция **card_number_generator**
Функция выдает номера банковских карт в формате "XXXX XXXX XXXX XXXX",\
где X — цифра номера карты.\
Генерирует номера карт в заданном диапазоне от 0000 0000 0000 0001 до 9999 9999 9999 9999.\
Принимает на вход начальное и конечное значения (как целые числа, так и строки) 
для генерации диапазона номеров.

### Модуль decorators
Содержит функцию-декоратор **log** для автоматического логирования начала и окончания\
выполнения функций, результаты выполнения или возникшие ошибки.
Декоратор принимает необязательный аргумент **filename**, для определения,\
куда записывать логи - в файл или в консоль:\
- Если **filename** задан, логи записываются в указанный файл
- Если **filename** не задан, логи выводятся в консоль.
Логирование включает:
- Имя функции, время начала и окончания выполнения при успешной операции.
- Имя функции, тип возникшей ошибки и входные параметры в случае ошибки.

### Модуль utils
Содержит функцию **get_transaction_data**, которая принимает на вход путь до JSON-файла\
и возвращает список словарей с данными о финансовых транзакциях.\
Если файл пустой, содержит не список словарей или не найден, возвращает пустой список.\
Файл с данными о финансовых транзациях operations.json находится в папке **data** 
в корне проекта.

### Модуль external_api
Содержит функции:
1) **get_transaction_sum** - принимает на вход словарь-транзакцию и возвращает сумму транзакции в рублях.\
Если транзакция в USD или EUR вызывается функция **get_exchange_rates** с обращением к внешнему сервису\
Exchange Rates Data API: https://apilayer.com/exchangerates_data-api для определения текущего курса валют\
и конвертации суммы операции в рубли. 
2) **get_exchange_rates** -  принимает на вход сумму транзакции и код валюты (EUR, USD)\
и обращается к сервису Exchange Rates Data API: https://apilayer.com/exchangerates_data-api \
для получения текущего курса валют и конвертации суммы операции в рубли 

### Модуль read_tx_files
Содержит функции для считывания финансовых операций из CSV- и EXCEL-файлов.
1)  **read_tx_csv** - принимает в качестве аргумента путь к файлу CSV.\
Выдает список словарей с транзакциями. Если файл не найден или не является CSV, выдаёт пустой список.
2) **read_tx_excel** - принимает путь к файлу Excel в качестве аргумента.\
Выдает список словарей с транзакциями.\
Если файл не найден или не соответствует Excel-файла, сообщает о соответствующей ошибке.
3) **find_delimiter** - сервисная функция для опредения разделителя в CSV-файле.\
Используется при чтении файла в функции **read_tx_csv**. 

### Mодуль config
Содержит переменные - пути к корневой папке приложения и к папке с тестовыми файлами.\
Используется в тестах и для логирования.

### Переменные окружения
Переменные окружения, использумые в проекте, должны находиться в файле .env, шаблон которого\
приведён в файле **example.env**

## Логирование
Для модулей **masks** и **utils** настроено логирование:\
запись логов в одноименный файл с расширением .log (н-р ""masks.log").\
Для всех логеров в модулях установлен уровень логирования: "DEBUG".\
Все логи записываются в папку **logs** в корне проекта.\
В репозиторий файлы логов не включены (см. **.gitignore**).

## Тестирование (Pytest)
### Для каждого модуля создан отдельный тестовый файл
- Для модуля **masks** - **test_masks**
- Для модуля **widget** - **test_widget**
- Для модуля **processing** - **test_processing**
- Для модуля **generators** - **test_generators**
- Для модуля **decorators** - **test_decorators**
- Для модуля **utils** - **test_utils**
- Для модуля **external_api** - **test_external_api**
- Для модуля **read_tx_files** - **test_read_tx_files**

#### В файле conftest.py - фикстуры со списками словарей, словарями и другими структурами для тестирования модулей
### В тестах предусмотрены проверки:
* на правильность работы функций маскирования номеров карты / счёта,
* на корректность преобразования даты в формат "ГГГГ.ММ.ДД"
* фильтрации списка словарей по статусу и сортировки по дате;
* на отсутствие входных данных - строк, списков, словарей, и их корректность;
* на корректность преобразования строк в числа или в даты.
* на коректность отбора транзакций по указанной валюте
* на случай отсутстия транзакций с указанной валютой
* при пустом списке словарей с транзакциями
* на корректность генерации номеров карт в указанном диапазоне
* проверка корректности начального и конечного значений (они должны быть цифровыми,
start не должен быть больше stop)
* на корректность работы функции-декоратора при успешном завершении работы декорируемой функции:
   - выод результатов в консоль и запись в лог-файл
   - запись сообщений об ошибках в лог-файл
* на корректное открытие файла с транзакциями и проверку его преобразования в объект Python
* проверка успешного и неуспешного запросов к сервису конвертации валют
* на корректное чтение CSV- и EXCEL-файлов и получение списка словарей с операциями
* на корректный поиск операций с указанным описанием
* на корректный подсчёт количества разных операций
